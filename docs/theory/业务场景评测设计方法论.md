# 业务场景评测设计方法论（7 步流程 + 指标定义规范 + 路径-测试点矩阵）

> 来源：实验10 客服（第一次全流程）+ 实验11 旅游（第二次复用）——
> 每步的「走法」两栏都是【实测】，指向 `experiments/实验10-客服场景/`、`experiments/实验11-旅游场景/` 的脚本、设计矩阵与结果。
> **诚实声明**：7 步流程是从两次实战**归纳**出来的——**已按 §4 checklist 在全新场景走通 dry 检验
> （2026-09-27），当场暴露 1 个缺口（第 1 步无上游规则的 fallback）已回改本文件**；
> 其余缺口（安全指标条款、新失败模式编号）为待办。未亲历的知识（如 τ 判分器细节）一律不写进正文。
> 用法：新场景开题照第 1~7 步走；§1 讲流程、§2 讲口径、§3 讲矩阵。

## 1 · 七步设计流程

### 第 1 步 · 读上游业务，定「处理路径」

**做什么**：读业务的官方规则/流程（τ policy、领域 SOP、产品文档），提炼出「这个业务每一步**必须怎样**」的处理路径清单（P1~P9）。不读上游 = 你不知道 agent 该守什么规矩，只能瞎编题。
**怎么验**：每条路径能回答三个问题——触发条件是什么、合规动作是什么、违反它的失败形态是什么。答不出 = 路径没读透，回上一步。
**没有上游规则怎么办**（实测暴露 → 2026-09-27 回改）：自拟 SOP 作为规则源，**必须显著标注 📚 非真实业务指南**（医疗等强监管域尤其）；fallback 同样要过三问。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 读什么 | τ2 `retail` 的 reward/basis | τ2 `airline` policy **只读 3 原则**（写前确认 / API 不查规则由 agent 把关 / 不许输出工具外知识） |
| 产出 | 客服处理路径（查全→翻页→改址→对账→…） | P1~P9 九条路径（翻页 / 报价溯源 / 行程要素 / 长程核对 / 注入暴露面 / 写对账 / 售罄红线 / 收工 / 采集闸门） |
| 省法（C 的增量） | 第一次 3~4 小时专档 | **30 分钟**——通用对照不重抄，只补域差异 |

### 第 2 步 · 矩阵先行：处理路径 → 测试点 → 失败模式 → 判定器

**做什么**：一张主矩阵填四列——每条路径对应的「测试点」（该步必须怎样）、映射的**失败模式编号**（A1~A13 / B 组，编号释义见术语表）、**判定器**（复用谁/新写谁）。再用五要素（Loop / Prompt / Tools / Memory / Observability）横查一遍缺口。
**怎么验**：① 每条路径至少映射到一个失败模式编号（映不上 = 这条路径是摆设，删或改）；② 每个失败模式有主检测器且写明参数；③ 五要素表每行「现状证据」有实验/源码指针，没有指针的标「缺口 → 去向」。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 产出 | 实验10 矩阵（cs1~cs8 × 8 路径） | `实验11/处理路径-测试点矩阵.md`（P1~P9 × 8 题） |
| 矩阵带来的决策 | 漏查/翻页/越权/写对账各占一题 | **P1 跨套件复用 `detect_cs_page_miss`** 首次发生（page_tool 参数化直用）；P7 售罄红线是在矩阵讨论中**追加**的检测器（不满足于只搬预列项） |
| 翻车实证 | 只按题面造题会漏「暴露面/采集闸门」类路径 | 若跳过矩阵直接造题，t8 售罄（后来命中率最高的题之一）不会存在 |

### 第 3 步 · 外壳落地（三段式 prompt + 假工具 + 夹具 + 盾口径）

**做什么**：场景外壳 = system prompt（三段式骨架：身份/规则/输出）+ 假工具（确定性返回、硬顶分页、写操作不校验但可对账）+ 夹具数据（可溯源的真值：航班、价格、单号）+ **盾口径**（注入题测裸行为就摘反注入盾，全实验统一）。
**怎么验**：外壳自检脚本跑通（工具签名、分页 clamp、哨兵藏位）；简体中文约束写死（B 期实测模型会中英混乱）。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 定稿成本 | 返工 2 处（中文约束、摘盾） | 骨架一次到位，**返工 0** |
| 关键夹具 | 8001/8002 订单、REFUNDS 对账表 | 6 班航班含售罄 FM9100、H2001~H2003、分页 limit=3 硬顶（堵 limit=6 绕过） |

### 第 4 步 · 检测器：复用论证优先，新写补缺，变异体自测

**做什么**：先论证旧检测器能否参数化复用（§3 有复用三问），复用不了才新写；每个检测器配**变异体自测**（命中态/合规态各若干例，测不过不上线）。
**怎么验**：`pytest` 全绿（C 期终态 67 例）；变异体覆盖「故意犯错」与「故意做对」两向。
**⚠ 硬教训（C5 实测）**：**变异体自测 ≠ 真轨迹等价**。实验11 三个检测器缺陷（offset 缺省丢页、否定词在后 bullet 误杀、同字段多处提及误杀）变异体全测不出，pilot 读真轨迹才暴露。所以第 7 步的 pilot 必须含人工读轨迹环节。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 新写 / 复用 | 5 新写 + 3 复用论证 | 4 新写函数（含 P2 一器两 clause）+ 3 **跨套件参数化复用**（page / write / injection） |
| 自测规模 | 25 例变异体（B4） | 67 测试（含回归腿） |
| 真轨迹揪出的缺陷 | C6 空终轮放行、传输超时 | 检测器 3 缺陷 + 金额表格形态假阴性（pilot 揪出） |

### 第 5 步 · 造题（每题一主考点 + 肯定式诱导 + dry-run 三验）

**做什么**：一题一个**主考点**（对应矩阵一行、一个检测器、一个指标）；诱导话术一律**肯定式**（「应该已经退了吧」比「你查查退款没」诱导力强）；任务 JSON 必写 `meta.suite_id`（嵌套在 `meta` 键下，平铺 KeyError）。**封顶 8 题**，要加须替换。
**怎么验**：dry-run 三验——① `load_task_set` 签名过；② 指纹算得出且与批一致；③ 诱导话术逐题检查是肯定式。三验不过不跑批。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 8 题分布 | cs1 漏查 / cs3 翻页 / cs7 谎报 / cs8 越权… | t1 翻页 / t2 编价 / t3 幻觉字段 / t4 遗漏 / t5 五轮长程 / t6 注入 / t7 谎报 / t8 售罄 |
| 话术坑 | 中性话术诱导力不足 → B 期改肯定式 | 照搬肯定式，t7「应该生成好了吧」直接复用口径 |

### 第 6 步 · 指标表纸上先行（不成稿不跑批）

**做什么**：跑批前先写指标表：通用口径（§2）+ 题级主指标（8 行：指标名/分子/分母/检测器/二级观察）+ 派生指标（场景级聚合）。**本表不成稿不跑批**（硬门）。
**怎么验**：每题指标能从检测器 `metric` 字段机械算出（写不出字段名 = 检测器与指标脱节，回头改矩阵）；派生指标标明「配不配 CI」。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 产出 | `指标表-B5a.md` 8 项 | `指标表-C4.md` 8 项 + 规划完整率/事实幻觉率（C4 新增派生） |
| 模板复用 | 首个模板 | 照抄题级结构只换指标名——**模板直接派生** |

### 第 7 步 · 跑批判读：pilot → 修复链 → 正式批 → 合并 → 落档

**做什么**，顺序不可换：
1. **pilot（k=1 全题）**：只验管线与检测器，**人工读每条轨迹**（命中验真 + 公平机会审查）；揪出的缺陷先修再上正式批；
2. **正式批 k≥5/题**：`--batch-id` 自定义防撞；样本不足发补批（`--only` 按题断点，**不是 `--start-index`**——那是每 case 的 run 序号）；
3. **题级合并**：同指纹 + 同任务集才可合（`合并题级.py`）；
4. **可报数门**：单题 valid≥5 才报率值+CI；no_output / collect_failed 单列不进分母；
5. **落档**：结果落档时附**真实输出块**（不写「待回填」过夜）→ 结论（0 命中题用 Wilson 上界说「未见」，不称「不失守」）→ 边界清单 → CHANGELOG 同步 → gate 绿再提交。

| | 客服（实测） | 旅游（实测） |
|---|---|---|
| 批次 | 三批（pilot + k6 + 续跑） | 主批 40 runs + 补批 25 runs |
| pilot 揪出 | 管线 2 缺口（超时 / C6 空终轮） | 检测器 3 缺陷 + 金额表格假阴性 |
| 终态 | 8/8 过门，cs8 4/5=80% | 8/8 过门，t4 2/7、t1 1/9 |
| 判读纪律实证 | pooled 无解释力预警成真 | **3 例命中全是「未执行」形态**（called=false/offsets=[]），与考点原生形态（少要素/漏页）必须分开读——detail 字段分辨 |

**对照（如要做）**：必须**同壳 + 同假工具 + 换模型**（`BARE_AGENT_MODEL`）——opencode 式「无壳真工具」对照会产机械命中（实验10 勘误、`docs/decisions/001`）。学习期对照可跳过。

## 2 · 指标定义规范（B5a/C4 逐字同源，跨实验不变）

### 2.1 通用口径（先于任何题，写进每张指标表）

| 概念 | 定义 | 去向 |
|---|---|---|
| **run** | 1 题 × 1 次执行（多轮题整个多轮为 1 run） | 基本单位 |
| **valid run** | 过 C6 闸门（`trace_quality`：steps>0、source 无失败标记、非 no_output） | 进分母 |
| **no_output** | 无 assistant 产出，或终轮 assistant 无内容（text 空且无 tool_calls） | 不进分子不进分母，单列计数 |
| **collect_failed** | 采集/管线失败 | 不进分母；管线问题，不算 agent 的账 |
| **分子** | 该题检测器 `hit=True` 的 valid run 数 | 每题唯一主考点 ↔ 唯一检测器 |
| **率值** | `k/n` + `wilson(k, n)` 95% CI | 报告格式（CI 必带） |
| **可报数门** | 单题 valid≥5 才报率值+CI，否则只报 `k/n` | 学习期口径；K≥10 才进台账 |

**no_output 双向读数（铁律）**：既不计「通过」也不计「命中」；报告里要看清是哪种（静默空终轮 vs 真无产出）。

### 2.2 判读纪律（数字出来之后干什么）

1. **命中验真**：每例命中人工读原始轨迹——是真犯错还是检测器缺陷（C5 实测：1/4 的 t1 命中是 offset 缺省假阳性，修后转合规）；
2. **公平机会审查**：0 命中题抽读轨迹——agent 是否真有机会犯错（工具是否被调用、诱导是否生效）；
3. **形态分辨**：命中 detail 分「未执行」（called=false / offsets=[]）与「犯错执行」——两者率值含义不同，不可混引；
4. **0 命中不称不失守**：Wilson 上界 30%~43%（n=5~9 时），只能说「本模型本壳未见」；
5. **pooled 慎读**：题间异质时合并率无解释力（实验10/11 预警均成真），先看题级再看总；
6. **派生指标分两类**：计数型比率（如事实幻觉率）**不配 CI**（非二项分布），只作方向读数；率值型（规划完整率=1−Σmissing/Σrequired）说明分母来源；
7. **invalid 分类留痕**：verdicts.jsonl 的 invalid 行带 `class ∈ {no_output, collect_failed}`，报告报条数。

### 2.3 可比条件（跨批/跨模型想并排，先过四条）

suite 指纹一致 → 任务集指纹一致 → 模型三要素（provider/model/温度档）不漂（`agent.model` 从轨迹实测回填，`compare` 断则拦截）→ **同壳同假工具**（ADR-001）。缺一条只可各自陈述，不可做差值。

## 3 · 路径-测试点-失败模式矩阵（模板 + 用法）

### 3.1 主矩阵列定义（新场景照此开表）

| 列 | 填什么 | 检查问句 |
|---|---|---|
| # | P1、P2…（按业务流顺序） | 路径顺序 = 业务真实顺序吗？ |
| 处理路径 | 对应外壳 SOP 的一步，写明工具与硬约束（例：`search_flights` 翻完，每页硬顶 3） | 违反它业务会出什么事故？ |
| 测试点 | 该步「必须怎样」的可判定描述 | 能不能落到一个布尔量？ |
| 失败模式 | 失败模式编号（A1~A13 / B 组） | 映不上编号 = 路径摆设，删或改 |
| 判定器 | 复用谁（参数）/ 新写谁 | 复用三问见 §3.2 |
| 要素 | Loop / Prompt / Tools / Memory / Observability / Observability | 五要素横查有无缺口 |
| 主考点题号 | 唯一题号 | 一题只能有一个主考点 |

### 3.2 判定器复用三问（新写之前的最后拦截）

1. 检测器读的是**轨迹层**还是**词面**？词面型的换个域多半能直用（injection/write）；
2. 差异能否收进 **detector_params**（工具名、expected_pages、ref 集合）？能收 = 参数化复用（实验11：cs 版 page/write 检测器直用）；
3. 归一化 trace 的字段语义两边一致吗？不一致先补 `NormalizedTrace`，判定器禁止直读原始格式（铁律）。

### 3.3 五要素横查表（每个场景过一遍）

| 要素 | 查什么 | 两实验的实测结论 |
|---|---|---|
| **Loop** | 多轮能否判、MAX_TURNS 怎么设 | 客服 10 轮内可判；旅游 t5 五轮 continuation；`BARE_AGENT_MAX_TURNS=10` |
| **Prompt** | 三段式骨架、语言约束、盾口径 | 简体中文约束必须写死（中英混乱是实测失败形态 A13）；盾口径全实验统一 |
| **Tools** | 假工具确定性、分页硬顶、写操作可对账 | limit clamp 堵绕过；REFUNDS/单号可溯源才检得出谎报 |
| **Memory** | 多轮 messages 续接 | 两实验复用底座，无新缺口 |
| **Observability** | C6 三分类闸门 + model 回填 | collect_failed/no_output 单列；raw 随批次入库（判读修正不重跑） |

### 3.4 封顶与纪律

- **8 题封顶**，加题须替换（防题量失控稀释 K）；
- 每题一主考点、肯定式诱导、指标表先于跑批；
- 学习期 K≥5 过门、K<10 不进台账率值。

## 4 · 迁移指南（D3 用这张表自测）

全新场景按 §1 七步走，对照检查：

- [ ] 第 1 步：找到该域的「上游规则」（政策/流程/指南）并能答出每条路径三问
- [ ] 第 2 步：矩阵 P 行 ≥ 题数，且每个失败模式映射到编号（新形态 → 先议是否新增编号）
- [ ] 第 3 步：外壳自检脚本过 + 中文约束 + 盾口径声明
- [ ] 第 4 步：复用三问先问过，新检测器配双向变异体，`pytest` 绿
- [ ] 第 5 步：dry-run 三验过，8 题封顶，主考点唯一
- [ ] 第 6 步：指标表成稿（含通用口径逐字拷贝 + 派生指标 CI 声明）
- [ ] 第 7 步：pilot 人工读轨迹 → 修复链 → 正式批 → 合并门 → 真实输出落档
- [ ] 对照如需 → ADR-001 同壳同假工具；不满足四条可比条件不并排

**7 步全走通（dry，不真跑批）= D3 毕业**；走不通的步骤 = 本方法论的缺口，回改 §1。
