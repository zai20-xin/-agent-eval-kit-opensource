# 术语与编号对照表（Glossary）

> **这是什么**：本项目**编号代号**、**自造术语**、**中英混排符号**的释义。
> 读任何文档卡在某个符号/词上，回这里查。
> **为什么要它**：本项目多套编号轴符号互相撞车（同一个 `B1` 在失败模式与任务编号里是两个意思）。
> 决定**不重命名编号**、改由本表消歧（见 [ADR-002](decisions/002-编号不重命名以术语表消歧.md)）。
> **维护规则**：新增编号轴 / 自造术语 / 中英符号，**必须在此登记**；与出处文档冲突时以出处文档为准并回改本表。

## 表 2 · 自造术语表

| 术语 | 人话解释 | 权威出处 |
|---|---|---|
| **外壳（场景外壳）** | 给裸 agent 套上的「人设 + 能力」包装：三段式 system prompt（身份/规则/输出）+ 一组工具（含假工具）+ 夹具数据 + 盾口径 | [方法论](theory/业务场景评测设计方法论.md) 第 3 步 |
| **假工具** | 外壳里为触发特定失败模式而设的工具（如永远失败的退款、硬顶分页），确定性返回、可对账 | [ADR-001](decisions/001-跨agent对照同壳同假工具.md) |
| **同壳** | 做对照实验时，两方使用**同一套外壳**（同 system prompt + 同（假）工具）；否则结果不可比 | [ADR-001](decisions/001-跨agent对照同壳同假工具.md) |
| **裸 agent（bare）** | `bare-agent/`：223 行最简 agent，作为被测对象 | [README.md](../README.md) 目录 |
| **盾口径** | 注入类题目测「裸行为」就摘掉反注入盾，全实验统一一种口径 | [方法论](theory/业务场景评测设计方法论.md) 第 3 步 |
| **夹具（fixture）** | 任务的固定真值数据（订单、航班、价格、单号），可溯源 | [README.md](../README.md) 落位表 |
| **变异体 / 变异自测** | 给**正确样本**人为注入一处缺陷，用来验证**检测器**抓不抓得住（测的是检测器，不是 agent） | [README.md](../README.md) 核心主张 |
| **可报数门** | 单题**有效 run ≥ 5** 才允许对外报「率值 + CI」；不足 5 只报 `k/n` 计数 | `experiments/实验10-客服场景/指标表-B5a.md` |
| **驱动（drive）** | adapter 里「怎么跑被测 agent 并采集轨迹」的动作 | [architecture.md](architecture.md) |
| **落位** | 新增产出应放进哪个目录（由 `tools/layout_gate.py` 门禁强制） | [README.md](../README.md) 落位规则 |
| **口径** | 指标/统计的分子、分母、valid 等计算规则 | [方法论](theory/业务场景评测设计方法论.md) §2 |
| **pooled** | 跨题/跨批合并汇总；附异质性，无解释力时不外推 | `experiments/实验11-旅游场景/指标表-C4.md` |
| **valid / no_output / collect_failed** | 单次 run 的状态：有效 / 无输出 / 采集失败 | [方法论](theory/业务场景评测设计方法论.md) §2 |
| **过门 / 过可报数门** | 达到「可报数门」门槛 | `experiments/实验10-客服场景/指标表-B5a.md` |
| **闸门（C6 闸门）** | `trace_detectors.py` 的有效性闸门，防止脚本自身故障被算成 agent 失败 | [architecture.md](architecture.md) |
| **指纹（fingerprint）** | 套件声明参与 sha256 哈希的源文件，用于跨批可比性判定 | [architecture.md](architecture.md) |
| **三要素可比** | `compare` 比对两批的「题目 / 判定口径 / 底座模型」，任一断则拒绝并排 | [README.md](../README.md) CLI |
| **跑批判读** | 指标表成稿后开跑，跑完**人工读真轨迹**判读（变异体测不出的缺陷靠这步暴露） | [方法论](theory/业务场景评测设计方法论.md) 第 7 步 |
| **收口 / 成稿 / 落地** | 该阶段任务完成并落档（全库泛用词） | — |
| **POC** | 方法演进脚本（`steps/01~07`），单跑、**不算正式实验** | [README.md](../README.md) 目录 |
| **兜底** | 备用机制（全库泛用词） | — |
| **横评** | 多个 agent 在同一任务集上的横向对比评测 | [architecture.md](architecture.md) |
| **并层** | 把散落的判定/统计实现归并进公共层（加 agent＝加一个 adapter；`wilson()` 移入 `evalkit.stats`），按粒度分两组、非新旧替代 | [architecture.md](architecture.md) |
| **机械命中 / 机械成分** | 因缺少工具或条件而**必然**发生、不代表真实能力的命中（如 opencode 没拿到场景假工具，查全必然为 0） | [ADR-001](decisions/001-跨agent对照同壳同假工具.md) |
| **方向读数 / 方向对照** | 只看「往哪个方向变」、不作精确数值解读的对照 | [ADR-001](decisions/001-跨agent对照同壳同假工具.md) |
| **三段式 prompt** | 场景外壳 system prompt 的固定骨架：① 身份与目标 ② 处理路径 SOP ③ 边界与红线 | [方法论](theory/业务场景评测设计方法论.md) 第 3 步 |
| **硬顶（分页硬顶）** | 工具分页上限被写死卡住（如 limit 固定 3），堵住「调大 limit 绕过翻页」 | [方法论](theory/业务场景评测设计方法论.md) 第 3 步 |
| **哨兵（哨兵藏位）** | 藏在夹具/工具返回里的标记值（如 `UPGRADE_PRESIDENTIAL_OK`），用于检测 agent 是否读到/泄露它＝注入是否中招 | [实验11 矩阵](../experiments/实验11-旅游场景/处理路径-测试点矩阵.md) |
| **主考点** | 一道题唯一的考察点，对应矩阵一行、一个检测器、一个指标 | [方法论](theory/业务场景评测设计方法论.md) 第 5 步 |
| **诱导话术 / 肯定式** | 出题话术设计；「肯定式」（如「应该已经退了吧」）比疑问式更易诱导出错误行为 | [方法论](theory/业务场景评测设计方法论.md) 第 5 步 |

| **台账** | 记录实测数字（率值 + CI）的台账表 | `experiments/实验10-客服场景/指标表-B5a.md` |
